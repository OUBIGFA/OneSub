# 字幕翻译实现与边界

## 处理流程

OneSub 使用用户配置的大模型服务。工作台的“AI 翻译”页选择目标语言、翻译风格、保存目录与“按意群重建时间轴”；点击“开始翻译字幕”直接运行。未配置服务时进入设置，不发送字幕。

1. 从完整原文建立上下文。短文本完整提供给各批次；长文本分段提取摘要与工作术语，再合并摘要。
2. 开启重建时，按字幕技能的接缝规则让模型输出逐行分段的原文；程序对齐回原文字词和时间证据。无词级时间只能合并，不能按字数虚构内部时间。ASS/SSA/VTT、受保护标记和锁定内容不参与重分段。
3. 按批次翻译，携带全局上下文与相邻字幕。使用编号到译文的 JSON 对象；逐条显示流式内容，未完成内容不写入正式字幕。
4. 容错解析处理思考标签、代码块及有限的不规范 JSON。缺漏、未翻译和结构问题带反馈重试；截断拆批，剩余缺译逐条补翻。不用原文填充失败译文。
5. 按目标语言配置执行确定性标点、空格处理，然后调用完整字幕技能的原检查器。
6. 校验项目版本、锁与来源范围后，整个结果作为一次可撤销修改写入译文轨。无检查错误时自动另存为带目标语言后缀的新文件；已存在的文件不覆盖。检查错误保留在工程和“检查结果”中，不自动导出。

识别附带的词级时间只在文字与时间范围可验证时启用。不可靠的词级证据会报告警告，仍保留可用字幕；不能把这种情况写成声学对齐已通过。

## 通用核心与可选风格

核心规则直接读取受控技能快照的 `SKILL.md`，按阶段加载断句、通用文风、阅读负荷及适用的语言规则。模型只负责当前操作；文件、时间、组装、检查、保存均由 OneSub 负责。提示词中的字幕、摘要和术语是数据，不可改变执行规则。

风格是声明式 `SKILL.md`，只补充措辞和领域规则，不执行脚本。通用风格不默认加载 3D 术语表：

- **通用**：通用文风及适用的语言规则。
- **3D / 动效 / VFX**：额外加载技术表达规范；中文目标再加载 `glossary-3d-zh.md`。
- **教学、科普**：额外加载技术表达规范，不加载 3D 术语表。
- 用户风格可声明受控 `references/*.md`；核心的忠实、锁定字面串与时间约束优先。

每次运行报告记录实际使用的规则文件及 SHA-256。用户术语单独作为锁定译法传入。

## 服务与续翻

支持 OpenAI Chat Completions 与 Responses 的流式协议。结构化输出依服务兼容性从 JSON Schema 到 JSON Object、普通文本逐级调整，最终仍须通过编号、内容和来源校验。

每次请求（含兼容调整、重试和补翻）计入用户设置的请求上限。瞬时错误采用有限退避；取消会终止当前运行。服务可能已对中断请求计费，因此不承诺所有失败请求都不重复计费。

已接受结果按端点、模型、输入、目标语言、规则、风格和术语等生成缓存键；重新运行复用相同条件下的完成结果。缓存不保存 API Key，未使用 30 天的结果在后续运行清理。缓存含字幕内容，只保存在本机用户数据目录。

MCP 的 `translate_subtitles` 使用同一翻译引擎、设置和检查器，返回新文件路径；有检查错误时返回工具错误，不发布文件。

## 验证入口

- `build/test.ps1`：原生界面、翻译协议、流式解析、补翻、缓存恢复、意群拆合、字词时间、锁与版本、真实字幕及技能 worker。
- `TestStylesAddTheirReferences`：通用/教学不载入 3D 术语表，3D 中文与英文目标各使用适用规则。
- `TestMCPTranslationSavesAndResumes`：官方 MCP SDK → 流式本地服务 → 真实检查器与字幕序列化；重复调用不再次请求已接受译文，也不覆盖旧文件。
- `tests/e2e/translation_provider.py`：真实桌面流式显示、完成前不发布、自动保存、不覆盖输入、撤销；使用受控协议夹具，不是模型质量评测。

真实服务与安装测试的范围见 [Windows 测试记录](verification/windows-0.0.1.md)。检查器只能证明其结构与阅读负荷规则的结果，不能证明全文翻译忠实或音画同步。第三方参考与实际复用边界见 [组件核查](research/implementation-reuse.md)。
