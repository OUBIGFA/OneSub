# OneSub 产品方案

状态：规划规格 · 2026-10-26

## 1. 定位与成功标准

OneSub 是本地优先的智能字幕工作台，帮助创作者完成：**导入 → 识别或提取 → 校对翻译 → 预览 → 交付**。核心用户是需要忠实表达术语、步骤和数值的课程创作者、技术内容译者，以及希望低学习成本制作字幕的个人用户。

产品的竞争力不是堆叠更多模型，而是把“原文有没有漏、时间有没有错、手改会不会被覆盖、最终视频是否一致”变成可检查、可恢复的流程。

成功意味着：

1. 首次使用者不阅读技术手册也能完成短视频字幕交付。
2. 没有云账号仍能完成本地识别、编辑和导出；没有识别模型也能处理已有字幕。
3. AI 不能覆盖已锁定的人工成果；任何自动合并、纠错或跨间隙操作都有可追溯来源。
4. 安装、下载、缓存和输出空间可见，不以“小安装包”掩盖首次运行数 GB 的模型下载。
5. 用户交付的是经过验证的文件，而不是只完成了模型调用的中间结果。

首发验证目标为 Windows x64；Windows 11 为首选环境，Windows 10 仅在 WebView2 与全部依赖仍支持且完成验收的具体系统版本上标兼容，不笼统承诺所有 Windows 10。macOS Apple Silicon、Linux x64 独立验收后发布。Windows ARM64、Intel Mac 和 Linux ARM64 本地 ASR 不纳入首发承诺。

## 2. 三种清晰入口

### 生成字幕

拖入或添加视频，先自动加载同目录同名字幕；找到字幕后直接进入校对，不要求重新识别。没有外部字幕时，有文本内封轨则优先建议“提取现有字幕”。需要识别的视频或音频再选择真实音轨、源语言和推荐模型，确认下载量与运行位置后开始。

### 翻译已有字幕

拖入或添加 SRT/VTT/ASS/SSA，自动关联同目录同名视频；没有匹配视频也能继续纯字幕工作流。选择目标语言、风格与翻译服务。ASS 默认进入“保留排版翻译”，而不是普通对白重排。

### 仅校对与导出

打开字幕或工程，修改文字与时间、检查问题、导出。不强迫使用 AI、不要求 API Key、不强制下载模型。

无时间文稿可以整理与翻译，但没有音频对齐证据时不得伪造定时字幕。只有音频的工程显示播放器与波形，不生成无意义的黑色视频。

### P0 首要流程：双向同名自动配对

参照 Subtitle Edit 的自动关联体验，**拖放和“添加文件”共用相同规则，默认开启**。例如目录内有 `课程01.mp4` 与 `课程01.srt`，添加任意一个，视频预览与字幕列表都应就绪，无需第二次选文件或点击“加载关联文件”。

1. 只查输入文件所在目录，不递归扫描其他目录。“同名”指移除最后一个扩展名后名称相同；保留章节号、标点与名称内部空格，不按相似度或截短名称配对。
2. Windows 下比较忽略大小写；其他平台先按实际文件系统语义匹配。大小写不同的多个实体仍视为多个候选，不能用遍历顺序决定。
3. 视频对应字幕限已验收的 SRT/VTT/ASS/SSA；字幕对应视频使用统一的可导入媒体列表，并经探测确认包含视频流。扩展名只用于筛选，不证明文件有效。
4. 唯一同名候选自动加载，状态栏提示“已自动加载字幕：课程01.srt”或“已自动关联视频：课程01.mp4”，并提供更换/解除关联。
5. 多个同名候选在准备区列出文件名、格式等必要信息，由用户选一次；不随意选第一个，也不把多份字幕叠加进编辑轨。没有候选时保留单文件流程。
6. `课程01.zh-CN.srt` 等带语言后缀的文件可列为“可能关联”，需用户选择；P0 不把 `课程01` 截短成 `课程` 后自动加载。自动配对只证明文件名对应，不证明内容版本和时轴同步。
7. 同时拖入明确的视频与字幕时优先使用用户所选文件，去重后一次导入。多组不同名称不连续覆盖当前工程，P0 先选一组，批量队列在 P1。
8. 重开工程时保留已保存的关联；新导入会替换现有内容时，先处理保存/新建/取消。自动发现不能覆盖手改或旧关联。
9. 候选读取、解析或视频探测失败时保留用户主动添加的文件，说明失败原因并允许更换。自动关联不启动 ASR、翻译、下载或上传。

详细入口见 [交互设计](ui-design.md)，实现边界与验收分别见 [架构](architecture.md)和[路线图](roadmap.md)。

## 3. 交付范围

### P0：可靠、易用的完整闭环

P0 分阶段开发，不是一轮做完全部功能。其发行底线包括：

- 工程创建、打开、自动保存、最近工程、媒体重定位、崩溃恢复和一致性备份。
- **视频/字幕双向同名自动配对**：拖放与添加一致，同目录唯一候选自动加载，多候选可选、失败可恢复。
- 视频/音频/字幕导入，文本内封字幕提取，音轨试听与明确选择，源语言选择。
- OneAsr 本地识别、真实时间证据、模型按需下载、取消、错误诊断与 CPU 路径说明。
- **一个主字幕列表**，可显示原译对照；原始、校正、译文修订可追溯；搜索替换、拆合、时间微调、至少 200 组撤销。
- 基础只读波形与当前句循环，便于核对时轴；复杂拖拽与多尺度批量校时留到 P1。
- 受控字幕翻译技能适配，术语预审最小入口、锁定词、批次审阅、选中重译、预算与发送范围提示。
- SRT/VTT/ASS 单语或受控双语输出；严格 ASS 翻译不隐式增加双语事件。
- 基础字体/位置/描边预设、ASS 预览、缺字检查；MKV 软字幕、MP4 软字幕与 SDR 硬烧录，提供 5 秒样片。
- 可定位的检查结果、修复前后对比、结果分支、防覆盖和完整导出报告。
- 当前任务及最近失败记录；高 DPI、键盘、IME 与基础读屏支持。
- 导入的说话人标签、音效说明、标牌和有意重叠受保护；允许人工标注说话人，但不宣称自动分离多人。

### P1：高频生产效率

- 多文件队列与批量套用设置；失败只重跑相关阶段；系列课程术语复用。
- 波形边界拖拽、快捷键吸附、双锚点漂移修复；文稿强制对齐和未匹配句审阅。
- 完整术语中心与 CSV/TSV/JSON 导入导出；同词异义、preferred/locked、来源与冲突预览。
- 本地翻译记忆库：按语言、领域、来源版本和审定状态保存；模糊命中只建议，禁止自动套用含不同否定/数值的相似句。
- 八类表达风格：3D/CG、通用口语、影视纪录片、IT/AI、学术科普、动漫游戏、商业财经、竖屏短字幕。只影响措辞与受约束分段，不改变事实。
- 双语独立样式、字体收藏与搜索、固定几何圆角底板、安全区、原硬字幕矩形遮盖/模糊。
- 多目标语言独立轨及审阅状态；译文包/术语/批注导出与安全回导，不加入实时协作服务器。
- 外部审校回导依据工程 ID、基准 revision、cue ID 或受控匹配；无 ID 的 SRT 先预览匹配与冲突，不按行号覆盖。
- 本地审核记录、已审/待审/有疑问过滤、批量交付清单、TXT/MD 文稿和检查摘要。

### P2：需要独立立项

PGS/VobSub OCR、自动说话人识别、人工可校正的场景切点建议、特定广播 TTML/IMSC/EBU 格式、指定版本的 FCPXML/Premiere/Resolve 交换、只读默认 MCP/CLI、显式后备 ASR、动态特效和 HDR 烧录。

不把 TTS、声音克隆、自动剪视频、实时字幕、网页抓取、云同步或插件市场隐藏进 P0。广播格式、平台预设和行业规范必须有版本和真实导入样例，不能以“支持 300+ 格式的底层库”宣称应用全部支持。

## 4. 内容与时间的产品契约

### 4.1 原始证据不变

原文件与识别 timeline 永久留存；纠错形成新修订，翻译形成独立轨或分支。重新识别、换模型、换术语、换样式均不删除旧成果。界面的“原文”必须注明是原始识别还是人工校正后的文本。

### 4.2 保真优先于简短

保留否定、条件、警告、不确定性、单位、数值、人物立场、操作顺序、快捷键与 UI 字面串。去口头填充只允许去掉零信息内容，且首版须确认；不得把后一句提前占用被删文字的时间。

字幕文本不是指令。字幕内的命令、地址、代码和所谓“忽略规则”只作为待翻译数据。

### 4.3 分段不制造时间

模型只选择来源范围，不输出新的数值时间码。有词/atom 锚点时使用真实切点；没有内部锚点的 cue 不按字符比例自动切轴。先保留边界并提示过长，或让用户对齐/手工打点。

来源范围覆盖是结构证明，不是语义完整证明。数值、否定、名称和前中后片段仍需人工抽检。

### 4.4 模式显式切换

| 模式 | 可以改变 | 不可隐式改变 |
| --- | --- | --- |
| 普通对白 SRT/VTT | 翻译、有证据的纠错和接缝修复 | 无证据内部切点、跨锁定区重排 |
| 保留时间翻译 | 文字 | 数量、顺序、ID、时间、设置与标记分配 |
| 保留排版 ASS/SSA | Dialogue Text 中允许翻译的语言内容 | 非 Text 字段、事件数/顺序、标签、已有换行与层 |
| 仅清理识别文字 | 有证据的纠错与断句 | 源语言、真实含义 |
| 无时间文稿 | 文本整理与翻译 | 自动生成时间码 |

普通单语对白默认每块一行，双语每种语言一行；多说话人和已有 ASS 换行按输入模式保留。**一行是可追溯的表达规范，不是所有平台的通用标准。** 技能阅读负荷用其语言配置，中文 4.5 DU/s；英文括号免计阅读负荷，但不免像素宽度检查。超宽先保真精炼、真实锚点重分段或调整样式，不能暗中缩小到难读、删词或换行绕过规则。

需要两行广播交付时另选经过授权与验证的规则配置；不能偷偷修改技能默认值。SRT/VTT 文件单行也不能保证所有第三方播放器不自动折行，外部播放器能力应在导出说明中交代。

## 5. 翻译与审阅

1. 解析全片，保护术语与实体。超上下文时分片阅读再合并摘要，不以开头摘要代替全文。
2. 展示短摘要和需确认的术语；普通用户可直接采用建议，高风险词与数字单独突出。
3. 按锁、语义区域、原间隙和 token 预算分批；前后文只读且不重复拥有输出权。
4. LLM 产生候选；程序检查范围、时间证据、格式、标识符、数字、锁和版本。
5. 只把有效候选放入审阅区；结构修复最多两轮，失败保留旧结果，不填原文伪装译文。
6. 默认按批次事务提交，后台返回的旧版本候选不得覆盖新修改。
7. 整文件组装后运行同一技能检查器，显示精确 errors/warnings。错误阻止正式发布；警告可说明理由后保留。

手改文字自动锁文字，改时间锁时间，拆合锁分段；“重译选中内容”默认只改译文。解锁与允许重分段是显式动作，撤销须恢复锁状态。

## 6. 交付体验

导出先选择用途，而不是面对编码器长列表：

- **字幕文件**：交给播放器或编辑软件，提供目标格式与兼容说明。
- **可开关字幕的视频**：推荐 MKV 保留 ASS；MP4 使用 mov_text，事先显示样式降级。
- **带固定字幕的视频**：SDR MP4，字幕无法关闭，视频需要重编码。

导出页展示目标语言、选中轨、文件名、输出位置、体积估算、原音轨/章节/附件处理、样式损失及校验状态。默认不覆盖源文件或已有成果。未知空间或耗时显示未知，不给虚假承诺。

用户可以先生成 5 秒样片。样片不是最终全片验收的替代，导出期间继续编辑也不能改变正在生成的版本。

## 7. 明确的限制与处理

- **本地资源成本**：默认 ASR 与 CTC 模型约 2.9 GB，仅为上游近似下载量；RAM/VRAM 门槛以实测公布。提供改存储位置、离线导入和空间清理。
- **多运行时维护**：Go、Rust、.NET、Python、WebView 和 FFmpeg 分工带来打包与安全升级成本。保留明确进程边界，不额外增加 Node 常驻服务或第二套默认 ASR。
- **识别不是事实判定**：静音、音乐、弱人声、夹杂语和重叠对白需专项测试；未知逐词置信度显示“未提供”，不编造可信分数。
- **严格保留与重排不能兼得**：严格 ASS 保护模式不做自动重分段；需要新的双语排版必须另建转换分支。
- **网络盘与同步盘不是活动数据库位置**：活动工程使用本地磁盘；共享通过一致性导出包，不把 WAL 目录直接多人同步。
- **AI 成本不是完全可知**：开始前估算、批次前预留额度，明确上限误差；请求结果未知时不自动重复付费调用。
- **隐私不仅是“不上传视频”**：字幕、摘要和术语也可能敏感。显示具体发送范围，提供本地处理模式；诊断与公开样例默认不含这些内容。

## 8. 功能取舍的方法

只有同时满足“高频用户价值、技术能力有证据、授权清晰、可定义验收”的需求才进入当前阶段。质量、可恢复性与易用性不能为增加更多风格/模型让路。

详细技术约束见 [架构](architecture.md)，具体界面见 [交互设计](ui-design.md)，完成标准见 [实施与验收](roadmap.md)。
