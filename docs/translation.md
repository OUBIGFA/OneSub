# 字幕翻译实现与边界

## 处理流程

OneSub 使用用户保存的大模型供应商。工作台的“AI 翻译”页可直接切换供应商和模型，设置并发批数、每批字幕数，并选择目标语言、翻译风格与保存目录。“按意群重建时间轴”是紧接主动作的强调色原生开关区；点击“开始翻译字幕”直接运行。未配置服务时进入设置，不发送字幕。运行中的任务使用启动时的配置，修改供应商或模型供下一次任务使用。

1. 从完整原文建立上下文。短文本完整提供给各批次；长文本分段提取摘要与工作术语，再合并摘要。
2. 开启重建时，普通字幕连续区间按约 30 分钟划分请求，30 分钟以内一批、一小时最多两批；边界落在就近的完整字幕之间，受保护内容会中断区间。该重建窗口不同于“每批字幕数”控制的译文请求批次。按字幕技能的接缝规则让模型输出逐行分段的原文；程序对齐回原文字词和时间证据。无词级时间只能合并，不能按字数虚构内部时间。ASS/SSA/VTT、受保护标记和锁定内容不参与重分段。
3. 按批次翻译，携带全局上下文与相邻字幕。使用编号到译文的 JSON 对象；逐条显示流式内容，未完成内容不写入正式字幕。
4. 容错解析处理思考标签、代码块及有限的不规范 JSON。缺漏、未翻译和结构问题带反馈重试；截断拆批，剩余缺译逐条补翻。不用原文填充失败译文。
5. 按目标语言配置执行确定性标点、空格处理，然后调用完整字幕技能的原检查器。
6. 校验项目版本、锁与来源范围后，整个结果作为一次可撤销修改写入优化字幕。原始字幕及其分段独立保留。无检查错误时自动另存为带目标语言后缀的新文件；已存在的文件不覆盖。自动保存、列表保存和另存为均只保存译文；双语字幕由导出时显式选择。ASS/SSA 的译文仍保留既有样式，优化字幕可单独导出。译文按实际分段来源显示“译文字幕（原始）”或“译文字幕（优化）”，不随当前优化开关改变。检查错误保留在工程和“检查结果”中，不自动导出。

识别附带的词级时间只在文字与时间范围可验证时启用。不可靠的词级证据会报告警告，仍保留可用字幕；不能把这种情况写成声学对齐已通过。

## 通用核心与可选风格

核心规则直接读取受控技能快照的 `SKILL.md`，按阶段加载断句、通用文风、阅读负荷及适用的语言规则。模型只负责当前操作；文件、时间、组装、检查、保存均由 OneSub 负责。提示词中的字幕、摘要和术语是数据，不可改变执行规则。

风格是声明式 `SKILL.md`，只补充措辞和领域规则，不执行脚本。通用风格不默认加载 3D 术语表：

- **通用**：通用文风及适用的语言规则。
- **3D / 动效 / VFX**：额外加载技术表达规范；中文目标再加载 `glossary-3d-zh.md`。
- **教学、科普**：额外加载技术表达规范，不加载 3D 术语表。
- 用户风格可声明受控 `references/*.md`；核心的忠实、锁定字面串与时间约束优先。

每次运行报告记录实际使用的规则文件及 SHA-256。用户术语单独作为锁定译法传入。

## 服务与续翻

供应商可新增、改名和删除，各自保存服务地址、接口类型、模型列表及上次选择。旧的单服务配置迁入一个供应商，已有 Windows 凭据继续可用。新供应商的 Key 按供应商身份与地址隔离，修改地址不会把旧 Key 发送到新地址。

模型的输入上限、输出上限、上下文上限只采用该供应商 `/models` 接口返回的值，或用户根据供应商文档填写的值。缺失值为 0，表示未知，不按模型名称猜测。输入和上下文上限用于记录与核对，不作精确 Token 或费用估算；已填写的输出上限传入对应接口的请求参数。

支持 OpenAI Chat Completions 与 Responses 的流式协议。结构化输出依服务兼容性从 JSON Schema 到 JSON Object、普通文本逐级调整，最终仍须通过编号、内容和来源校验。

每次请求（含兼容调整、重试和补翻）计入用户设置的请求上限。未产生完整字幕的瞬时错误采用有限退避；已产生完整字幕的断流保留结果并停止该请求。取消会终止当前运行。服务可能已对未完成的请求计费，因此不承诺中断请求都不重复计费。

任务将已显示的文字、已完成标记、输入、分段和上下文写入本地进度文件；不写入 Key。中断后保留列表和“重试”按钮。再次启动应用会恢复中断现场，不自动发起请求。点击“重试”使用当前选择的供应商和模型，只请求尚未完成的字幕；目标语言、风格、输入和已确认的分段保持该任务的设置。原文已经修改时拒绝套用旧进度，要求重新开始。未完成文字只供查看，不能当作完整译文保存或导出。

已接受结果按端点、模型、输入、目标语言、规则、风格和术语等生成缓存键；重新运行复用相同条件下的完成结果。缓存不保存 API Key，未使用 30 天的结果在后续运行清理。缓存含字幕内容，只保存在本机用户数据目录。

MCP 的 `translate_subtitles` 使用同一翻译引擎、设置和检查器，返回新文件路径；有检查错误时返回工具错误，不发布文件。

## 验证入口

- `build/test.ps1`：原生界面、翻译协议、流式解析、补翻、缓存恢复、意群拆合、字词时间、锁与版本、真实字幕及技能 worker。
- `TestStylesAddTheirReferences`：通用/教学不载入 3D 术语表，3D 中文与英文目标各使用适用规则。
- `TestMCPTranslationSavesAndResumes`：官方 MCP SDK → 流式本地服务 → 真实检查器与字幕序列化；重复调用不再次请求已接受译文，也不覆盖旧文件。
- `TestRebuiltTimelineLeavesOriginalTrackIndependent`、`TestVersionOneProjectRecoversOriginalTrackBeforeRebuild`：原始与优化字幕独立编辑、撤销、重开，以及旧工程的备份和迁移。
- `TestExportSeparatesOriginalRebuiltAndTranslation`：分别回读原始字幕、优化字幕、译文和双语 SRT/VTT，并核对各自的分段与文件名。
- `TestTranslationSavesOnlyTranslatedText`、`TestTranslationExportDefaultsToSingleLanguage`：预览为双语时，译文保存与默认译文导出仍只选择译文。
- `test_single_line_export_preserves_times_and_format_metadata`：导入双语 SRT/VTT/ASS 后提取上行或下行，保留时间、单行条目、内联样式及格式元数据；不改输入文件。
- `tests/e2e/translation_provider.py --interrupt`：真实桌面断流、测试进程意外退出、启动恢复和重试。服务核对第二次请求只有缺失字幕；使用受控协议夹具，不是模型质量评测。

真实服务与安装测试的范围见 [Windows 测试记录](verification/windows-0.0.1.md)。检查器只能证明其结构与阅读负荷规则的结果，不能证明全文翻译忠实或音画同步。第三方参考与实际复用边界见 [组件核查](research/implementation-reuse.md)。
